# Odoo 19 社区版 扫码套件（7 个模块）

版本：stock_barcode_ce 19.0.2.1.0；stock_barcode_print_ce 19.0.1.0.0（新增）；barcode_camera_ce、product_barcode_quick、purchase_barcode_ce 19.0.1.1.0；其余 19.0.1.0.0。LGPL-3。全部模块均为自研，未使用企业版代码。

## 模块与依赖

## 安装

把部署脚本和模块包放在服务器同一个目录下，然后：

```
chmod +x deploy-barcode-ce.sh
./deploy-barcode-ce.sh --check      # 先只做环境检查，不改任何东西
./deploy-barcode-ce.sh              # 部署到 staging-odoo / staging
./deploy-barcode-ce.sh --prod       # 部署到 prod-odoo / letaoge
```

脚本会：检查容器、addons 目录、PDF 工具版本、Pillow、workers 配置 → 备份现有模块目录 → 解压 7 个模块 → 安装/升级 → 重启容器 → 检查启动日志 → 打印回滚命令。
默认容器、数据库、路径写在脚本开头，可用 `--container` `--db` `--addons` 覆盖。
**数据库不会自动备份，正式库请先自行 pg_dump。**
语言为简体中文时界面自动显示中文（已附 zh_CN 翻译）。

## 2.1 新增：标签直连打印、扫码报废与退货、两个限制的补救

### 标签机直连打印（新模块 stock_barcode_print_ce）

工作方式：仓库里任一台电脑运行一个小程序（打印代理），它主动连 Odoo 取任务，再把指令发给标签机。**仓库路由器不用开任何端口**，手机（含 iPhone）也能触发打印。

安装代理（脚本随交付的部署脚本一起放在同目录，也在模块 `tools/` 下）：
```
# 常驻运行（Linux/树莓派；Windows/Mac 同样可用）
python3 label_print_agent.py --url https://<你的 Odoo 域名> --token <代理令牌> --db letaoge
```
令牌在「条码 → 配置 → 标签打印 → 打印代理」里新建后获得。建议做成系统服务开机自启。

打印机在「条码 → 配置 → 标签打印 → 标签打印机」里配置：
- 目标：`tcp://192.168.1.50:9100`（网口机）、`cups:队列名`（Linux/Mac 的 USB 机）、`win:打印机名`（Windows 的 USB 机）
- 指令：TSPL（TSC、佳博、芯烨、汉印等）或 ZPL（斑马）；203 / 300 dpi；标签尺寸和间隙
- 表单上有「打印测试标签」按钮

可打印：商品标签（扫码界面菜单里按本单已扫数量打）、批次/序列号标签、库位标签、包裹标签（库位和包裹列表里选中后用「打印」菜单）。没有配置打印机时自动退回 PDF。
中文是在服务器上先画成图片再发给打印机，所以打印机没有中文字库也能打中文；条码用打印机自带条码指令。
**首次使用请打一张测试标签**：如果文字是黑底白字，在打印机上勾选「反转文字位图（TSPL）」即可。

### 扫码报废

主菜单「报废」入口，只有扫码主管可见：扫库位（可选）→ 扫商品（有批次的扫批次）→ 填数量 → 选原因 → 确认。数量超过库存、或缺批次时会拦截。

### 扫码退货

已完成的单据在扫码界面里点「创建退货单」，系统按原单生成退货单，再逐件扫实际退回的数量、验证即可。扫码员也能操作。

### 两个旧限制已补上

- 扫码员扫到未知码：显示「申请建档」，提交后进「条码 → 商品申请」；同一条码重复提交会累计次数；商品建好后申请自动关闭。
- 过期批次：扫码界面直接提示哪些批次过期；扫码员无法放行，主管确认后才能验证。

## 2.0.0 新增：多人同扫、实时刷新、弱网暂存

**多人同扫一张单**：扫码不再修改共享的明细行，而是每扫一次新增一条「扫码事件」，已扫数量由事件汇总。
沙箱实测：10 人同时扫同一张单各 30 次，300 次全部成功、零冲突、零重试（1.x 版在 6 人并发时约 5% 被拒）。
事件表（stock.barcode.scan.event）同时是下一阶段对账数据集的原始数据。

**实时刷新**：同一张单被别人扫了，你的手机约 0.3 秒内自动更新；页面上显示「某某也在处理这张单」（最近 2 分钟有扫码的人）。
需要 Odoo 多进程（workers>0）且反向代理开启 WebSocket——你的环境已满足。推送内容只有单据 id 和用户名，不含数量等业务数据。

**弱网暂存（当前打开的单据）**：
- 每次扫码带唯一编号，先存在手机上再按顺序发送；网络断开时继续扫，页面显示「离线：N 条扫码待同步」，并在对应商品上预显示 +N。
- 恢复网络（或每 2–15 秒自动重试）后按原顺序补传；服务器按编号去重，重发不会重复计数（已测）。
- 离线期间「验证」「装包」「加商品」自动禁用；补传后被服务器拒绝的扫码（未知条码、违反规则）集中列在「恢复网络后被拒绝的扫码」里，不会悄悄丢失。
- 刷新页面或关掉重开，未发送的扫码仍在（保存在本机浏览器）。
- 范围：扫码作业界面（收货/发货/调拨/批量）；盘点界面仍需在线。

```
docker exec -it staging-odoo odoo -d <数据库> -i stock_barcode_print_ce -u barcode_camera_ce,product_barcode_quick,stock_barcode_ce,sale_barcode_ce,purchase_barcode_ce,pos_barcode_ce --stop-after-init
```

**升级前请让扫码员把手上的单据先扫完或暂停**，升级时扫码界面会短暂不可用。

## 1.1.0 新增：管控与追溯

**角色**（设置 → 用户 → 权限 → 条码扫描）
- 扫码员：只能用扫码界面，看不到也改不了库存后台；登录后直接进扫码界面。
- 扫码主管：扫码员权限 + 可越过「禁止手填数量」、可按预留数量整单验证、可应用盘点、可把未盘设为 0、可查看扫码日志。
- 原有库存用户/管理员自动拥有扫码主管权限，使用方式不变。

**作业类型扫码规则**（库存 → 配置 → 作业类型 → 扫码规则 页签，每项单独开关）
- 必须扫源库位（发货/调拨）
- 必须扫目标库位（收货/调拨）
- 禁止手填数量（同时禁止手动加商品、禁止未扫整单验证）
- 必须装包才能验证
- 拒绝单据外商品
- 拒绝超出需求数量

**扫码日志**（条码 → 扫码日志）
每次扫码、手填数量、装包、验证、盘点操作都记一条：时间、用户、设备、条码、识别结果、商品、批次、库位、数量（手填时含原数量）、单据、成功/警告/错误。只能追加，不能修改。可按用户/操作/日期分组，筛选「错误」「手填数量」「强制验证」。字段带数据格式版本号（schema_version=1），下一阶段的对账服务直接读取。

**条码数据体检**（条码 → 配置 → 条码数据体检）
上线前在正式库副本上点「开始体检」，列出：校验位错误、会被条码规则误读成称重/价格/批次的码（如 21–23 开头的 13 位码、10 开头的码）、重复使用的码、没有条码的商品、没有条码的可存货库位。只读；可一键为没有条码的商品生成店内码。

**欠单确认**：部分完成时由扫码界面直接询问「创建欠单 / 不创建欠单」，不再弹出后台向导（扫码员没有后台权限）。

## 上线前必须确认

- **HTTPS**：摄像头只在 HTTPS 下可用（Nginx Proxy Manager 已满足）。扫码枪不受影响。
- **PDF 工具**：标签尺寸依赖 `wkhtmltopdf 0.12.6.1 (with patched qt)`。在容器里执行 `wkhtmltopdf --version` 确认。官方 odoo:19 镜像自带此版本。
- **库存设置**（库存 → 配置 → 设置）：按需开启「存储位置」「批次和序列号」「包裹」。货位生成器会自动开启「存储位置」。
- **GS1**：如果要扫 GS1-128 条码，把 库存设置 → 条码规则 改为「Default GS1 Nomenclature」。
- **POS 当场建商品**：操作员需有「商品 / 管理员」权限，否则按 Odoo 原逻辑只提示未知条码。
- **校验位检查**：默认开启，只在新录入/修改条码时生效，不影响已有数据；可在 设置 → 商品条码 关闭。

## 使用入口

- 顶部菜单「条码」→「扫码作业」：仓库扫码主界面（手机优先设计）。
- 「条码」→「扫码查商品」：查价/查库存/未知码建档/打印标签。
- 「条码」→ 配置 →「生成货位」：一次生成 区-架-层-格，条码格式 `仓库代码-A-01-1-01`。
- 库位 / 包裹列表 → 打印 → 热敏标签。
- 调拨单、批量调拨表单上有「扫码」按钮，可直接进入扫码界面。
- 指令条码表：作业类型记录 → 打印 → 条码指令表（验证、装包、清除、打印、主菜单）。

## 扫码规则速查

- 收货：扫商品（可连扫）→ 扫目标货位，已扫的行放入该货位。也可先扫货位再扫商品。
- 发货：扫来源货位 → 扫商品。扫到别的批次按实际扫到的批次出库。
- 调拨：扫来源货位 → 商品 → 目标货位。
- 追踪批次/序列号的商品：扫商品后扫批次/序列号；GS1 码一次带出商品+批次+数量。
- 整箱码（商品包装单位的条码）：扫一次按箱内数量计入。
- 包裹：扫空包裹码/新包裹码 → 后续商品装入该包；扫有货的包裹码 → 整包出库。
- 验证：只处理已扫数量，其余按作业类型设置生成欠单；一个都没扫时会先确认是否按预留数量全部验证。
- 盘点：扫货位 → 扫商品；可一键把未盘到的设为 0；「应用」后更新库存。

## 沙箱测试结果

Odoo 19.0 社区版 + PostgreSQL 16 + wkhtmltopdf 0.12.6.1 (patched qt) + 无头 Chromium：
（2.1 版）83 项自动化测试全部通过，其中 11 个是在真实浏览器中操作的界面流程（摄像头窗口、扫码查商品建档、收货、发货欠单、盘点、扫码员受限操作、断网暂存与补传、扫码报废与退货、扫码员申请建档、销售单扫码、POS 未知码建档）。另验证了从 1.0.0 → 1.1.0 → 2.0.0 带数据升级；Odoo 自带库存测试 639 项在装与不装本套件时结果完全一致；并发 10 人×30 次零冲突；1 万商品/300 行单据每次扫码服务器耗时中位 18 毫秒；两浏览器实时刷新约 0.3 秒；离线暂存与重发去重在浏览器中实测；标签直连打印做了真实端到端验证（真实 Odoo 服务器 → 真实打印代理程序 → 模拟网口标签机，收到完整 TSPL 指令，任务状态变为已打印）。实际打印机上的出纸效果需在你那边验收。
